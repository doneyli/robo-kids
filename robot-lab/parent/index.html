🛠️ How this actually works

The page talks straight to the robot. There is no server of ours in the middle — the Reachy Mini daemon runs a web API on port 8000 and answers cross-origin requests, so a static HTML file is a legitimate robot client.

Every command goes through one of these:

POST /api/move/goto              head pose, antennas, body yaw, duration
POST /api/move/set_target        instant target, for realtime control
POST /api/move/play/wake_up      and /goto_sleep
POST /api/move/play/recorded-move-dataset/{dataset}/{move}
POST /api/motors/set_mode/{enabled|disabled|gravity_compensation}
POST /api/volume/set
GET  /api/state/full             live pose, antennas, control mode, DoA
GET  /api/daemon/status          is the backend running?

Angles are radians and distances metres on the wire. The app works in degrees and millimetres and converts at the last moment, in assets/js/reachy.js.

Safety. Head pitch and roll are clamped to ±40°, head yaw ±180°, body yaw ±160°, and head-minus-body yaw to 65°. That last one is a coupled limit — each axis can be legal while the pair is not. Clamping happens before the request is built, so the on-screen robot and the real one always agree.

Full API docs live on the robot itself, at http://reachy-mini.local:8000/docs, whenever he is powered on.
